## Cadence over cramming

The set of tools, commands and shortcuts is effectively infinite. Trying to absorb them in a burst overwhelms and does not stick. The chapter's rhythm: small daily improvement, at least one new item per week. Small, steady increments are more sustainable and better retained.

## Collaborative learning playbook

Colleagues are the richest source of productivity tips.

- Ask: when someone uses an unfamiliar tool, command or shortcut, ask about it, without embarrassment for not knowing.
- Show: when a teammate does something the slow way, demonstrate the faster way, and have them repeat it three or four times so it sticks.
- Onboard: help colleagues install and start using your favorite tools. It deepens your own understanding and spreads a familiar setup across the team (handy for pairing; teams may agree on a shared baseline).
- Pairing: if the partner uses something new to you, ask for a lesson; if you know a shortcut they lack, teach it.
- Forums: run occasional lunch-and-learns where people demo tools. Never assume others already know what you know.
- Humility: attend sessions about tools you consider yourself expert in; there is usually something new.
- Weekly budget: a few minutes per week learning something about your tools, then share it.

## Keeping up with languages

Languages and frameworks evolve, so coding habits should too:
- Read release notes for each new version and try the new features.
- Look for chances to apply them in real code.
- Teach them; lead a study group using "see one, do one, teach one."
- Consider contributing to the language or framework community; many welcome it.

## Personal knowledge management (PKM)

The volume of incoming information (podcasts, posts, videos, tutorials) demands a deliberate capture-and-organize practice. Pain it prevents: knowing you once had the answer but not where it went.

Rules:
1. Write it down. The same problem will return, for you or a teammate, and memory will fail.
2. Treat notes as external storage for the brain.
3. Form does not matter. Informal is fine. Digital is easier to search and share than paper, but paper works if it is used.
4. Make it portable and mobile. Insights and recommendations (a book, a podcast, a fix idea) arrive away from the desk; the system must accept them anywhere.
5. Decide how web resources are handled: synced, organized bookmarks or a dedicated bookmark manager (Pinboard is the book's example).
6. When you learn a new command, record it immediately.

## Choosing a PKM medium

| Option | Strengths | Weaknesses |
|---|---|---|
| Paper scraps or pocket notebook | Zero setup, always at hand | Hard to search and share |
| Plain notes file or document | Simple, searchable, portable if synced | Structure is up to you |
| Org Mode | Plain text, powerful, Emacs-native | Learning curve |
| Evernote, Notion and similar | Rich media, web clipping, mobile apps, flexible structure | Vendor lock-in, can invite over-organizing |

Co-author Dan's Notion usage shows the kinds of content a PKM should hold for an engineer: research notes when learning a new technology (notes, snippets, images, links together), first drafts of process or feature documentation in Markdown, reusable checklists (for example a code review checklist), and general notes captured via mobile app and browser clipper. He calls it his second brain, while stressing that tool choice is personal.

Co-author Nate's counterexample: a colleague's binder clip of handwritten scraps, accumulated over years, reliably produced the exact answer when asked. Lesson: the best system is the one that actually works for its owner. Simplicity is not a defect.

## Capturing conference talks

Many conferences publish recordings. Pick the talks you care about, build a personal playlist, and consume them like podcasts during walks, workouts or commutes, possibly at faster playback speed.

## Practice plan (own adaptation)

- Week 1: pick one repetitive task and automate it inside a strict timebox; share the result.
- Each week for the next few months: adopt one new keyboard shortcut and log it in your notes.
- A fixed 15-minute weekly slot (end of the week works well): browse your editor's docs and enable its tip-of-the-day or the terminal equivalent; note one surprise.
- Monthly: review your knowledge system. Are you finding things when you need them? If not, simplify or switch.
- Quarterly: revisit an existing automation and see if it can absorb a larger part of the workflow.
- Ongoing: keep experiments timeboxed so they never become the work.
