# Career and collaboration (Fundamentals of Software Engineering, ch. 1, 13, 14)

Becoming an engineer is less about a language than about scope, judgment and working with people. This theme covers the mindset, the soft skills and the deliberate management of a career.

## Cross-chapter rules

1. **Engineers own the whole lifecycle.** Scalability, reliability, security and maintainability, not just code that runs.
2. **Understand the problem before solving it.** Find the real need behind requests, ask why repeatedly, keep a domain glossary, and fix causes rather than symptoms.
3. **Be strategically lazy.** Think first, search before building, and treat brute force as a first draft.
4. **Fresh eyes are valuable.** Question inherited practices with curiosity, and write code for the next reader.
5. **Choose communication channels on purpose.** Match warmth and record to the message, assume messages persist, run meetings with agendas and small invite lists, and rehearse presentations.
6. **Translate technical work into business value** for non-technical audiences.
7. **Influence without authority.** Frame proposals around the decision maker's priorities, start small, recruit allies, and map stakeholders by power and interest.
8. **Guard focus time.** Long blocks for deep work, clustered meetings, hard work at peak hours.
9. **Plan the career backward** from a 3 to 5 year target with milestones; explore by trying things, and remember most moves are reversible.
10. **Keep evidence and relationships.** A dated wins log, a network built on mutual value, interviews treated as two-way, and sustainable habits, especially when remote.

## Default workflow

1. Clarify the problem and stakeholders before proposing solutions (ch01, ch13).
2. Pick channels, plan influence and protect focus time (ch13).
3. Set a career target, a learning radar and a wins log; review them quarterly (ch14).
